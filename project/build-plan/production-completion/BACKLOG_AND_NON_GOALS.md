# Later backlog, non-goals and complexity guardrails

## Later enhancements

Consider richer planning templates/recurrence, semantic retrieval, forecasting, additional work nesting, advanced visual dependency exploration and performance optimization beyond accepted budgets only after the canonical local workflow is accepted. Give each a new decision/task ID and measurable user benefit. They do not need dormant commands or speculative schema now.

## Explicit non-goals for this declared release

No replacement app or v1 runtime import. No second database/lifecycle/action engine in TypeScript or workflow Markdown. No generic programmable workflow platform before typed fixed rules work. No microservice or event-sourcing rewrite just to appear architectural. No remote multi-host coordination, global project dashboard, mandatory automated harness launch or web UI. No Windows support claim without a separately qualified target scope. No tamper-proof promise against an actor with unrestricted local filesystem control.

No direct client display-status assignment, implicit gate success, unpermissioned force switch, hidden cross-project fallback, fake launch proof, fabricated reviewer, or "complete enough" production status that omits a mandatory safety/recovery/native gate.

## Keep complexity proportionate

Use existing abstractions when they preserve the correct boundaries. A sealed submission solves execution-versus-review ownership; do not generalize it into an arbitrary event framework. A typed recoverable job solves SQLite/external side effects; do not distribute every transaction. Cycle assignments solve scheduling history; do not keep an extra writable sprint hierarchy. Separate revision meanings solve false conflicts/stale authority; name each only where it has a real invariant.

Plan helper scripts are optional read-only coordination aids. They do not need to become another work operating system. When Boreal can safely represent the plan, build an explicit supported import adapter as a separate bounded task rather than assuming plan.json already matches a public API.
