## 5. Ordered implementation / investigation instructions

1. Keep selected project/root/database epoch/service identity visible and bind requests, caches and subscriptions to it.
2. On project switch, cancel/quarantine old requests and reject late responses from the previous project.
3. Represent live/stale/unavailable/incompatible separately from last-known task status; show timestamp and scope of cached data.
4. Disable mutations when current authority/snapshot is unavailable while preserving readback and diagnostic navigation.
5. Persist only minimal project-bound pending-operation identity needed for readback, not a second canonical database or offline lifecycle queue.
6. Reconnect via snapshot resync after cursor gaps and resolve unknown outcomes before retry.
