## 2. Outcome and why this task exists

Build and install the full product as one versioned artifact set, verify actual runtime identity, and make updates atomic/recoverable without risking project databases.

**Task outcome:** Freeze package contents, provenance and supported runtime policy. The ordered work and named acceptance checks below define its boundary; do not replace them with a broader rewrite or a thin scaffold.

**Known context/risk:** Source ZIP integrity and fake-release wizard fixtures are not production release proof. Existing update/upgrade routes must verify what was installed, not infer a version from output.

**Inherited M02 coverage:** S06-T02  
**Known findings to inspect/reproduce:** AR08  
**Final acceptance rows:** Contributes to its sprint exit gate and linked acceptance matrix; not a stand-alone release claim.

## 5. Ordered implementation / investigation instructions

1. Define required bin/bwrk, complete TUI distribution, wizard, workflow/skill/spec/share assets and metadata for every supported target.
2. Bind binary/TUI/schema/API/status/workflow/memory/toolchain identities to one source commit/tree and artifact manifest.
3. Enforce the approved actual linked SQLite/runtime features and supported Node/compiler policy on each release target.
4. Distinguish source archive, built candidate package, installed prefix and published artifact identities.
5. Specify reproducibility expectations, signature/checksum origin and immutable artifact naming.
6. Reject mixed-source, stale-binary or missing-required-asset packages before staging.
