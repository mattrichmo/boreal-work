# Plan execution state and evidence semantics

`plan.json` owns scope/dependencies. `execution/STATE.json` records execution facts and is initially empty/unaccepted. These are planning artifacts, not a replacement Boreal operational database or a supported import schema.

## Task states

| State | Meaning |
| --- | --- |
| not_started | No assigned execution attempt. |
| assigned | Named worker/input/write set allocated; required dependencies accepted. |
| in_progress | Worker is executing within the allocation. |
| blocked | A named input, finding or capability prevents safe progress. Preserve partial artifacts. |
| awaiting_integration | Worker changes exist, but shared patches/combined-tree checks remain. |
| ready_for_review | Bounded handoff and evidence submitted; not accepted. |
| accepted | Coordinator verified the named task's acceptance at an exact source/artifact identity. |
| rejected | Submitted result did not meet acceptance; retain it and start a new attempt if retried. |

Derived dependency readiness is not stored as a truth-changing status. A task can have accepted dependencies and still lack a reviewer/platform or write token. Release publication additionally requires explicit authority. Accepted leaves remain subject to sprint review/reconciliation; their acceptance does not mean the sprint passed.

## Minimum accepted record

Record task/attempt, worker, reviewer or accepting reviewer as applicable, exact input and accepted source identities, handoff path, evidence references with digest/outcome, changed paths and actual integration boundary. Gate records also identify reviewed leaves, independent reviewer and finding/revalidation records. A reviewer must not be the implementation principal being independently approved. Non-code work uses exact document/contract hashes instead of inventing binary evidence.

Unknown outcomes remain unresolved until authoritative readback. Rejected/expired attempts and failed evidence are append-only history; don't overwrite the old attempt object. The helper validates presence/graph consistency, not the actual truth of a claimed pass. The coordinator must inspect artifacts and independence.

## Plan changes and release state

Decision records bind approved contract versions and authorizers. External capability records include actual supporting evidence. Adoption remains not_adopted until the required contract adoption gate. A final release decision is an attributable record on qualified artifacts, not a state string toggled because every card exists.

## Revalidation findings and corrective children

A new correction uses `kind: remediation`, an unused task ID below T90, accepted implementation/T90 prerequisites and explicit inclusion in T91 prerequisites. T90 does not retroactively depend on corrections generated by that same review. Failed T92 attempts are referenced as evidence, not treated as accepted prerequisites. Before changing the graph, preserve the prior gate attempt in history and mark the latest affected gate blocked/pending a new attempt; never retain a live accepted gate whose new dependencies are unmet. Already-started successors require an explicit impact/quarantine decision. T92 reruns on the corrected combined tree.
