**Sprint:** [BW-S00](../SPRINT.md)

**Dispatch:** `operator_only`  
**Priority:** `9`  
**Acceptance profile:** `focused`

## Outcome / user value

Make the versioned `recover` action emitted by Boreal guidance callable through
the supported Rust CLI and service. This is an operational repair required to
resolve expired attempts and resume the already-imported S00 work without
bypassing its claim, fence, proof, or gate rules.

## Current context

At project revision 25, T01 and T04 are `expired_review`; guidance emits an
allowed `recover` action with project/entity/proof revisions, attempt/fence,
session, operation ID, confirmation, and a typed recovery disposition. The
public command registry only exposes `recovery list` and `recovery resolve`.
Those commands do not submit the descriptor-bound recovery action. See
`PLAN_CHANGE_001.md` and the `recover_route_audit` handoff for observed evidence.

## Work

1. Map the existing `Recover` descriptor to the application-owned expiry and
   recovery-obligation lifecycle; keep `recovery resolve` as a distinct
   identity-bound operation.
2. Add a public typed command and service route that accepts the current
   descriptor inputs and rechecks project, entity, proof, attempt, fence,
   session, confirmation, role, and disposition at the canonical mutation
   boundary.
3. Preserve idempotent operation receipts and recovery history. Stale,
   cross-project, incomplete, or unauthorized requests must reject without
   changing state.
4. Register the route in the callable command registry and ensure its syntax
   and input contract agree with trusted guidance.
