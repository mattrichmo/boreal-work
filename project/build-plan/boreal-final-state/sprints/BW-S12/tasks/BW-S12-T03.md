## Work

1. Guide an operator from an empty project through source/config selection, enrolled worker and scoped session setup. Test a genuinely enrolled Agent; using an Operator principal is not proof that automatic worker dispatch works.
2. Preserve actor, session, harness, project, source/config and action descriptor identity through start/resume/checkpoint/heartbeat/renew/release/finish. The harness owns liveness scheduling; heartbeat is not renewal and neither extends the hard deadline.
3. Capture/bind the changed result to the current attempt before verification and submission. Keep the original claim inputs immutable; invalidate stale evidence/review applicability when result or proof identity changes.
4. Expose canonical review decisions and closeout receipts/summary readback after client restart. Keep needs-review, rejected, released, cancelled and accepted distinct. Independent approval stays role- and submission-bound.
5. Qualify lost replies, long tool calls, expired leases, stale fences, service/process restart and handoff. Read back an uncertain operation before retry; preserve abandoned work before reassigning. Use S00-T05 recovery and distinct obligation resolution rather than replacing them.
6. Check authorization again at each mutation boundary. A returned guide, confirmation flag or forged role/session field cannot create grants or permit self-attested trusted evidence.

## Required revision 4 general-work delta

1. Extend existing pinned acceptance/proof machinery with attributable artifact inspections and human/independent decisions. Keep command receipts valid and unchanged; do not fake a shell command to approve a logo or research report.
2. Support configurable rigor with bounded registered profiles: lightweight completion attestation, required-deliverable validation, reviewed artifacts and existing software verification. Profile names and versions are frozen by T01; retain focused/reviewed compatibility and never silently weaken an already-pinned software profile.
3. Separate producer assertion, automatic validation and authorized acceptance. Require correct actor/reviewer separation only when the selected profile demands it. A human approval is an explicit decision with identity, time, rationale and exact submission, not a fabricated trusted execution receipt.
4. Evaluate required output coverage, type/cardinality, availability and exact revision before close. Optional missing outputs are visible but not blockers; missing required outputs, stale files or rejected reviews block close. Summaries cannot satisfy independent evidence by themselves.
5. Retain claim fencing, immutable input identity, deadlines, operation idempotency, rejected/failed history and recovery. Requirement/input/result changes invalidate applicability, not historical facts. Blocked reviews do not keep an expired worker lease alive indefinitely.
6. Cover revised master assets, stale derivative review, same actor review where prohibited, rejected-then-revised submission, duplicate approval/readback, cancellation and restart. Ordinary enrolled agents must execute a mixed-work pilot without Operator impersonation.
