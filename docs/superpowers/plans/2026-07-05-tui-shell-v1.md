# TUI Shell v1 Plan

Scope: shell + Global(Overview, Projects, Queues) + Repo(Roll-Up, Sprint Board,
Task Detail). Everything else in TUI_SURFACE_CONTRACTS.md is a stub route.

## Data path decision

- Global routes: spawn `bwrk dashboard global --json` (existing pattern in
  `load.ts`). The composite payload already has `registry`, `globalQueues`;
  route loaders slice it per-route into a `TuiEnvelope`.
- Repo Roll-Up / Sprint Board / Task Detail: **direct store read** via
  `FileBorealStore`, same pattern `loadTuiData` already uses today (not a CLI
  spawn). Deviation from the brief's default ("keep load.ts's spawn-CLI
  pattern"): no CLI command currently emits a rollup tree or work detail
  envelope with graph edges, and the contract doc's own Open Questions flag
  this gap. Membership/scope derivation reuses the exact `blocks`-edge +
  `dependencyIds` logic already duplicated between `apps/cli/src/commands/
  shared.ts#dependencyIdsForWork` and `apps/tui/src/load.ts#childWorkIds` -
  factored once into `packages/ui-model/src/tui-contracts.ts` as
  `computeScopeIds`/`childWorkIds` and reused by the new rollup builder.
- Event-log head poll: construct a fresh `FileEventLog` per tick and call
  `.head()` (bypasses in-process cache so cross-process writes are seen).
  Noted: `.head()` reads the whole file on a cold instance, so "cheap" is
  aspirational for large logs - fine for v1, tail-read is a follow-up.

## Files

- `packages/ui-model/src/tui-contracts.ts` (new, exported from index.ts):
  `TuiSurfaceKind`, `TuiEnvelope`, `TuiLimits`, `TuiTruncation`,
  `TuiEntityKind`, `TuiEntityRef`, `TuiNavFrame`, `TuiFilterState` family,
  `TuiActionEffect`, `TuiCommandDescriptor` + `buildCommandDescriptor()`,
  `TuiRouteRequest`, rollup view types (`RollupNodeKind`, `RollupNodeView`
  with split `workStatus?`/`health?`, `RollupProgressView`,
  `RollupBlockerSummary`, `RepoRollupView`, `RepoRollupSummary`), plus the
  pure `childWorkIds`/`computeScopeIds`/`buildRepoRollupView` builder.
- `apps/tui/src/routes.ts` (new): route id enum per surface, left-rail
  section list with number-key bindings 1-9, stub route ids for out-of-scope
  pages (renders "planned").
- `apps/tui/src/route-nav.ts` (new): nav reducer over `TuiNavFrame` stacks;
  push/pop preserves cursor + filters; global->repo drill keeps the global
  frame as `returnFrame` on the repo stack's root so `esc` at repo root pops
  back to it with cursor intact.
- `apps/tui/src/loaders.ts` (new): `loadRoute(request: TuiRouteRequest):
  Promise<TuiEnvelope<TBody>>` dispatch by routeId; global loaders spawn CLI,
  repo rollup/board/detail loaders read the store directly (task detail is
  fetch-on-enter only, never preloaded for the whole list).
- `apps/tui/src/head-poll.ts` (new): `watchHead(workspaceRoot, onChange)`
  polling `FileEventLog.head()` every ~2s.
- `apps/tui/src/shell.tsx` (new): top bar, context strip (surface/workspace,
  filters, stale badge, "data: Ns old"), left rail, body slot, footer key
  hints sourced from route binding specs.
- `apps/tui/src/command-panel.tsx` (new): confirmation panel for write/danger
  `TuiCommandDescriptor`s (displayCommand + workspaceRoot + subject); read
  actions run immediately without a panel.
- `apps/tui/src/routes/rollup.tsx`, `sprint-board.tsx`, `task-detail.tsx`,
  `global-overview.tsx`, `global-projects.tsx`, `global-queues.tsx` (new):
  per-route body renderers over the loader's envelope body.
- `apps/tui/src/index.tsx`: wire to the new shell (`RouteApp`) instead of the
  legacy `App`. Legacy `app.tsx`/`nav.ts`/`bindings.ts`/`search.ts` stay in
  the tree (their existing tests still pass) but are no longer imported by
  `index.tsx` - flagged as follow-up cleanup, not deleted here.
